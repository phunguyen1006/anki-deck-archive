# Compatibility and limitations

Designed for Anki Desktop 26.08.1 and 26.09; other versions disable integration. Both corresponding Python backends passed the isolated test suite. Themes, high DPI, keyboard navigation, other add-ons, actual sync and mobile have not been verified. Treat this as experimental, and use a test profile and backup.

The archive container and its subtree are hidden by ID-scoped styles in the main deck list when archive metadata is consistent. They remain accessible through Browse and on other clients. A metadata inconsistency leaves the rows visible; inspect the manager. This integration depends on Anki's current deck-row HTML and has not yet been verified in the running desktop UI. An automatic statistics filter is applied to the modern statistics search field when a new window opens; it can be disabled in Archive Manager and may be changed in Statistics. The integration uses a search-field ID described as an external API in Anki source, but its live end-to-end behavior has not been verified. Legacy Statistics and third-party graphs are unaffected. Automated recovery is not implemented. Filtered decks, Default and deck trees containing filtered decks are unsupported. Cards currently in filtered decks prevent archiving their original deck. Existing filtered decks, parent limits, current deck selection and cross-device changes may affect study behavior; do not study archived decks. External dashboards, mobile stats, and today's deck-browser summary are unchanged.

Config sync is not a transactional multi-device archive protocol. Avoid concurrent archive operations across devices. Collection-wide All Statistics may include deleted-card history, while filtered searches do not. Active graphs reflect current card membership; they do not describe which deck held a card at the time of review. Not every graph has been individually validated. Metadata is stored in a single collection config object and is intended for modest numbers of archived roots, not huge manifests.
