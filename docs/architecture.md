# Architecture

`core/service.py` validates deck identity, stores collection-specific versioned metadata, moves deck subtrees, resolves destinations and builds the search. `ui.py` installs the deck menu, manager and statistics entry using Qt and Anki hooks. Mutations use `CollectionOp`; queries use `QueryOp`. No cards are exported, imported, deleted, suspended or rewritten by this add-on.

The container name is chosen only after checking for an existing user deck, and its ID is saved. A record is written before a deck is renamed; if that operation fails, the manager marks a record outside the container as needing attention. Restore only removes a record after verifying the new name. An existing destination is never intentionally overwritten. A renamed original parent is identified by ID; if it is missing, the old path is proposed. Anki may create missing parent decks on rename. If a record is orphaned or the container contains unrecorded roots or direct cards, Active Statistics refuses to produce a potentially misleading filter. Manually inspect and restore a backup when uncertain; the add-on does not automatically repair records.

The public render hook provides HTML rather than a tree filter. The add-on appends row-specific CSS for the verified container and descendant IDs before rendering; it does not replace or parse the generated HTML. If validation fails, rows remain visible. This depends on Anki's deck row structure and may interact with other add-ons. Do not manually add unrelated decks or cards to the container. Changes to archived decks made outside the add-on can invalidate metadata.

The modern statistics hook initializes Anki's own search field with the active scope when the per-collection preference is enabled. A visible notice explains the scope and warns when initialization fails. The user may change the scope in Anki afterward. The search uses current card membership and does not alter cards or review logs; other statistics surfaces are unaffected. Legacy graphs are not intercepted.
