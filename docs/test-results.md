# Verification report

Environment: Windows, Python 3.14.7, isolated `anki==26.9` / `aqt==26.9` and `anki==26.8.1` / `aqt==26.8.1` packages, Qt 6.12.0 from pip. Anki Desktop 26.08.1 was subsequently detected running on the machine. All collection tests use temporary collections, not a user profile. The 12 tests passed on each backend.

`python -m pytest -q --tb=short`: 12 tests passed, 0 failed. Tests cover nested and Unicode names; empty decks; new and suspended queues; selected card scheduling fields, note fields, IDs and revlog before and after; duplicate and Default rejection; a pre-existing container name; conflict refusal; parent rename and reopen; invalid, missing and unrecorded metadata; a simulated rename failure; undo/redo; native backend graph card and today-review counts; and synthetic 15,000-card search counts before archive, during archive and after restore (15,000/5,000/15,000). The synthetic large fixture reuses notes and is not a representative scheduling, sync or performance benchmark. Backend graph calls use Anki's internal Python backend for testing; UI uses the supported manual search interface.

After adding deck-list hiding, the same command on the 26.8.1 backend passed 15 tests. The three added tests check the identified archive subtree, exclusion of active deck IDs, and failure to hide when archive records or contents are inconsistent. A simulated deck-browser hook checks generated selectors and the fail-open shortcut. These checks do not verify the live desktop render or third-party add-on interactions.

The 0.2.0 suite adds checks for the saved statistics preference and a simulated statistics hook with successful and failed page loads. It passed 17 tests on each of the Anki 26.8.1 and 26.9 Python backends. The Qt manager was instantiated offscreen with its collection query stubbed, and its default checkbox was checked. Attempts to run `tests/webengine_smoke.py` in an isolated Windows Qt environment terminated before producing a result (process exit `-1073740791`), including after matching Qt and WebEngine library versions. Therefore the automatic search dispatch has not been verified in a live WebEngine statistics page. The release is experimental.

For 0.2.1, the Anki 26.8.1 suite passed 23 tests; after extending the layout check to update the success message, its six geometry cases and the existing statistics-hook check passed again on both the 26.8.1 and 26.9 Python environments. The offscreen Qt checks exercise the actual layout with a stand-in graph widget, testing normal and error notices at three window sizes and after resizing. They do not exercise the live Anki WebEngine window.

An offscreen Qt smoke check instantiated the empty manager with its collection query stubbed. It is not an interactive desktop test. Python compilation and package ZIP validation were run. Initial test collection failed because pytest imported the root module outside Anki; the entry point now skips installation when no Anki main window exists. The first offscreen smoke attempt initialized Qt before importing Anki's web engine; importing Anki first fixed the test setup. Neither issue was a successful desktop integration test.

Not tested: installed Anki Desktop and add-on installation; end-to-end UI or actual Stats window; light/dark/follow-system appearance; high DPI; keyboard flow; actual sync, conflicts, one-way sync or mobile; other add-ons; FSRS and learning/relearning states; all individual graphs; real 50,000/100,000-card collections; media; filtered-deck interaction beyond the implemented guard; interrupted operating-system or sync failures; and full data-integrity comparisons across every Anki field. No claim of stable or production readiness is made.
